- 已运行相关验证命令，或明确说明为什么跳过。

- 如果模块职责、数据流、数据结构或公开行为变化，已评估 `docs/architecture.md`。
- 如果工作规则、保留文档、红线或必要检查变化，已评估 `AGENTS.md`。
- 如果目录级规则变化，已评估相关局部 `AGENTS.md`。
- 如果本计划引入新的活跃设计说明和执行计划组合，已将旧组合移动到归档目录。
- 如果首次出现归档项或归档关系变化，已建立或更新 `docs/archive/INDEX.md`。
- 最终总结说明了哪些文件被更新、哪些文件被评估但没有修改，以及原因。

## 规则

- 执行计划正常完成后，不要把执行计划变成长期状态看板。
- 持久结果和决策写入 `docs/changes.md`。
- 只有执行计划被中断时，才填写“如果中断”。
- 如果新的执行计划取代旧的活跃执行计划，旧执行计划移入 `docs/archive/plans/`，并在 `docs/changes.md` 中记录取代关系。
- 执行计划不替代设计说明；如果任务意图或边界变化，应先更新或创建设计说明。
- 执行计划不替代变更记录；如果产生长期决策，应写入 `docs/changes.md`。
