# V0.7.3 Topics and Scoring Calibration Spec

## Status

Active design note for V0.7.3.

## Intent

Calibrate topic keywords and scoring thresholds after the 2026-W21 real weekly run.

The real run showed that the first keyword for each lane drives default source preview and crawl planning. Several first keywords were too broad, and scoring produced too many `S_candidate` items.

This is a configuration-only calibration step. It is not a new feature expansion.

## Scope

In scope:

- Reorder or replace first lane keywords in `config/topics.yaml`.
- Keep existing source enablement unchanged.
- Raise `S_candidate` threshold in `config/scoring.yaml`.
- Reduce the metadata score for merely having an abstract.
- Increase the penalty for missing abstracts.
- Update maintained project continuity docs.

Out of scope:

- Source client changes.
- Enabling PubMed, bioRxiv, medRxiv, Crossref, or Semantic Scholar.
- Changes to `config/sources.yaml`.
- Code changes.
- SQLite schema changes.
- JSONL export format changes.
- PDF downloading.
- LLM ranking or LLM summaries.
- Zotero, Obsidian, Anki, Telegram, or email integration.
- Vector databases.

## Calibration Inputs

The 2026-W21 run produced 80 candidates, with 74 classified as `S_candidate`. OpenAlex/Zenodo duplicates and broad keyword matches were overrepresented.

Key calibration decisions:

- Make first lane keywords narrower because `max_queries_per_lane: 1` uses only the first keyword by default.
- Move broad keywords such as `embodied intelligence`, `dynamical systems`, and `semiotics` out of the first position.
- Raise `s_candidate_min` from 18 to 22.
- Lower `metadata.has_abstract` from 8 to 6.
- Change `missing_abstract_penalty` from -3 to -6.
