# V0.7.4 Report Duplicate and Repository Noise Suppression Spec

## Status

Active design note for V0.7.4.

## Intent

Reduce duplicate-title and repository-like pollution in weekly candidate reports after the V0.7.3 real run.

The V0.7.3 calibration reduced `S_candidate` inflation, but the report still contained repeated titles, OpenAlex/arXiv mirror records, and Zenodo-like repository entries.

This is a report-stage ranking and selection refinement. It does not change source crawling or stored data.

## Scope

In scope:

- Add report-stage near-duplicate title suppression in selection.
- Downrank non-kept duplicate-title candidates with reason `Near-duplicate title`.
- Prefer higher score; when duplicate scores are close, prefer arXiv, then non-repository OpenAlex, then repository-like OpenAlex.
- Add configurable repository-like scoring penalty.
- Surface repository-like penalty in score details and score audit penalty stats.
- Add focused tests for duplicate-title suppression, arXiv/OpenAlex mirror preference, repository-like penalty, and reject/downrank log visibility.
- Update maintained docs.

Out of scope:

- SQLite schema changes.
- Source crawling behavior changes.
- Changes to `config/sources.yaml`.
- Enabling new sources.
- PDF downloading.
- LLM ranking or LLM summaries.
- Zotero, Obsidian, Anki, Telegram, or email integration.
- Vector databases.

## Report Contract

Weekly report and score audit continue to read candidate JSONL exports. They may select fewer duplicated titles because duplicate-title candidates are downranked before lane balancing.

Reject/downrank logs include `Near-duplicate title` groups when duplicate-title suppression applies.
