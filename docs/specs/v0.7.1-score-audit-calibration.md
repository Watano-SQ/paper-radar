# V0.7.1 Score Audit Calibration Spec

## Status

Active design note for V0.7.1.

## Intent

Add a score-audit report for real weekly trial runs so scoring behavior can be inspected before downstream workflows depend on it.

The audit is a calibration and debugging tool. It is not a recommendation model and does not produce final reading grades.

## Scope

In scope:

- Read existing candidate JSONL exports.
- Use the existing runtime config, scoring config, scoring layer, and lane balance layer.
- Generate a compact Markdown score-audit report under the runtime reports directory.
- Report candidate level counts, lane stats, source stats, component stats, penalty stats, near-threshold candidates, rejected/downranked summaries, and deterministic calibration notes.
- Support `--config-dir`, `--export-file`, `--output-dir`, `--per-lane`, and `--compare-no-scoring`.

Out of scope:

- LLM calls or LLM ranking.
- PDF downloading.
- Zotero, Obsidian plugin, Anki, Telegram, or email integration.
- Vector databases.
- OpenReview, CORE, or IEEE clients.
- Google Scholar or publisher HTML scraping.
- SQLite schema changes.
- JSONL export format changes.
- Source crawling behavior changes.

## Report Contract

Default command:

```bash
uv run python -m src.report.score_audit
```

Default output:

```text
data/reports/score_audit_<YYYY-WW>.md
```

The report audits score behavior only. It should remain compact enough to inspect after a weekly trial run.
