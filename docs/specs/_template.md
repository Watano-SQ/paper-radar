## 约束

- 除非明确需要，否则保持当前仓库结构；
- 不要假设尚未实现的行为；
- 不确定事实标记为“需要人类补充”；
- 任务边界应足够小，能够被一个活跃执行计划承接；
- 不要把执行步骤写进设计说明。

## 验收标准

- 可观察结果；
- 验证命令或可检查产物；
- 文档同步预期。

## 规则

- 当前活跃设计说明放在 `docs/specs/`。
- 被取代的设计说明移入 `docs/archive/specs/`。
- `docs/specs/` 中除 `_template.md` 外，只保留当前活跃设计说明。
- 如果项目明确需要多个并行活跃任务线，必须在 `AGENTS.md` 中说明并行规则。
- 设计说明只表达任务意图、边界和验收标准，不承担执行状态记录。
- 如果设计说明被取代，必须在 `docs/changes.md` 中记录取代关系。
