# V0.6.5 Runtime Configuration Spec

## Status

Active design note for V0.6.5.

## Intent

Decouple Paper Radar runtime paths from hardcoded local script assumptions while preserving the current local CLI defaults.

This prepares the core pipeline for later packaging contexts, including possible Obsidian-related workflows, without implementing an Obsidian plugin.

## Scope

In scope:

- Centralize runtime path and config loading through `src.app`.
- Add `config/app.yaml` for local output paths and filename templates.
- Preserve default local paths for `data/`, `data/raw/`, `data/exports/`, `data/reports/`, `logs/`, and `data/papers.sqlite`.
- Support `--config-dir` for the main pipeline, diagnostics, and weekly report commands.
- Support minimal environment overrides for runtime output paths.
- Keep source clients independent of project-root discovery.
- Keep diagnostics read-only.

Out of scope:

- Obsidian plugin implementation.
- Writing to an Obsidian vault.
- Scoring, LLM ranking, LLM summaries, PDF downloading, Zotero, Anki, Telegram, email, OpenReview, CORE, IEEE, vector databases, Google Scholar, or publisher HTML scraping.

## Configuration Contract

`config/app.yaml` is the maintained local runtime path config. Relative paths resolve under the project root. Absolute paths remain absolute.

Supported environment overrides:

- `PAPER_RADAR_CONFIG_DIR`
- `PAPER_RADAR_DATA_DIR`
- `PAPER_RADAR_REPORTS_DIR`
- `PAPER_RADAR_EXPORTS_DIR`
- `PAPER_RADAR_LOGS_DIR`
- `PAPER_RADAR_DATABASE_PATH`

The `obsidian` section is scaffolding only. `obsidian.enabled` defaults to `false`, and no Obsidian write behavior exists in V0.6.5.
